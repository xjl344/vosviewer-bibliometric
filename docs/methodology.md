# 方法学说明

本文档记录本工具在方法学上的设计决策，以及**真实数据踩出来的坑**。
如果你在做文献计量研究，这些经验可以直接用在你的论文里。

---

## 一、分析流程

```
文献导出文件
    ↓  ① 解析（自动识别格式）
    ↓  ② 关键词清洗 + 同义词归并
    ↓  ③ 领域过滤（可选，剔除检索污染）
    ↓  ④ 构建共现网络（全/二进制/分数计数）
    ↓  ⑤ VOSviewer 计算布局与聚类
    ↓  ⑥ 导出图片（网络/叠加/密度）
    ↓  ⑦ 生成报告（含方法学段落、研究空白检验）
```

---

## 二、指标定义

### 共现强度

三种计数方式：

| 方式 | 定义 | 适用 |
|---|---|---|
| `full` | 关键词每出现一次计一次 | 默认，最常用 |
| `binary` | 每篇文献内只计一次 | 抑制「同一篇里重复出现」的影响 |
| `fractional` | 按文献内关键词数均分 | 抑制「关键词多的文献」的影响 |

### 关联强度

本工具报告用的关联强度为：

```
a_ij = c_ij / (w_i × w_j)
```

其中 `c_ij` 为共现次数，`w_i`、`w_j` 为两词出现次数。

**注意**：这只是用于报告的近似值。**VOSviewer 内部会自己计算关联强度**，
图上显示的连线粗细以 VOSviewer 的结果为准（它使用相同的 association strength
归一化，但基于它自己的权重定义）。

### 模块度 Q

衡量聚类划分的「干净程度」，取值 −0.5 到 1：

| Q 值 | 含义 |
|---|---|
| > 0.5 | 聚类结构非常清晰 |
| 0.3 – 0.5 | 结构可接受 |
| 0.1 – 0.3 | 结构较弱 |
| < 0.1 | 结构很弱 |

**Q 由 VOSviewer 的聚类结果反算**，保证报告与图一致。

### 中介中心性

衡量节点在网络的「桥接」作用。中介中心性高的关键词连接了多个研究群落，
是领域内的枢纽概念。

计算方式为 Brandes 算法（通过 `networkx`，未安装时该指标不可用）。

## 三、研究空白的统计检验

### 为什么需要检验

光看「实际共现 / 期望共现」比值会把噪声当成研究空白。

期望共现的估计：

```
E[共现] = (词A频次 × 词B频次) / 文献总数
```

实测案例：120 篇文献中，「智能家居 × 居家养老」实际共现 0 次、期望 1.9 次，
比值 0 看着极惊人。但统计检验 **p = 0.113**，完全可能是偶然。

### 检验方法

若两词彼此独立，则「同时出现的文献数」服从超几何分布：

```
X ~ Hypergeometric(N, n_A, n_B)
```

其中 `N` 为文献总数，`n_A`、`n_B` 为两词各自出现的文献数。

单侧 p 值：

```
p = P(X ≤ 实际观测值)
```

**p < 0.05** 表示：若两词真的互不相关，观察到这么低的共现次数的概率不足 5%。

### 同一批数据的检验结果

8 个跨聚类低共现词对中，**只有 1 对达到显著**：

| 词对 | 实际 | 期望 | p 值 | 判定 |
|---|---|---|---|---|
| 智慧养老 × 智能家居 | 0 | 3.17 | **0.0227** | ★ 可用 |
| 智慧养老 × 居家养老 | 0 | 2.00 | 0.0996 | 不可引用 |
| 智能家居 × 居家养老 | 0 | 1.90 | 0.1131 | 不可引用 |

**报告会把结果分成两节**：「显著的研究空白」（可引用）与「未达显著的词对」
（明确标注不可引用）。

### 局限

**统计显著 ≠ 有学理意义。** 检验只说明「不太可能是随机波动」，
不说明「两个词属于同一研究领域」。必须人工核查标题确认没有检索污染
（见 `limitations.md` 陷阱 2）。

## 四、同义词归并

### 为什么必须人工确认

同义词判断依赖领域知识。工具负责「把候选找出来并按可能性排序」，
最终决定权留给研究者——因为**这个词表要写进论文的方法学部分**。

### 候选发现的两条规则

1. **编辑相似度**：字符串相似度 ≥ 阈值（默认 0.88）
2. **包含关系**：一个词是另一个的子串

第 2 条是中文语料的必需项。中文靠加修饰词造新词，
包含关系的相似度往往只有 0.7 左右，单靠相似度阈值会漏掉。
实测 689 个中文关键词，相似度法只找出 4 组，加上包含关系后多找出 6 组。

**但包含关系噪声很大**：「健康」是「健康中国」「健康促进」「健康素养」……
十几个词的子串，显然不该把那些词全吸收掉。所以需要消歧。

### 用共现率消歧（关键设计）

核心洞察：

> **真正的同义词很少同时出现在同一篇文献里**——作者会选其中一个写法。
> **相关但不同的概念则经常共现**——作者会同时用它们。

因此：

```
共现率 = |docs(A) ∩ docs(B)| / min(|docs(A)|, |docs(B)|)

共现率低（≤ 0.30） → 很可能是同义写法 → 建议合并
共现率高（> 0.50） → 很可能是不同概念 → 不要合并
```

实测效果：

| 词对 | 共现率 | 判定 |
|---|---|---|
| 影响因素 / 影响因素分析 | 0.00 | 同义，可合并 |
| 身体素养 / 澳大利亚身体素养框架 | **1.00** | 不同概念，不合并 |
| 条件风险感知 / 无条件风险感知 | **1.00** | **意思相反**，绝不合并 |

### 映射链与循环

自动归并按词频选规范词，人工规则可能与之冲突，形成环：

```
自动：older adult → older adults（因为 older adults 频次更高）
人工：older adults → older adult
⇒ 环："older adult" ⇄ "older adults"
```

环一旦形成，结果取决于遍历顺序，两个词形都可能残留。
**实测真实数据踩到过这个坑。**

解决（两层）：
1. **人工规则优先**：铺完自动映射后，把人工规则的「目标词」从自动映射的键里摘掉
2. **解析映射链**：`a→b, b→c` 归一为 `a→c, b→c`；遇环取环内字典序最小的词作终点

## 五、检索污染的处理

### 问题的严重性

宽泛的检索式会捞进大量不相关文献。实测某份 120 篇的数据里，
**45 篇（38%）与研究生题无关**（轨道交通、消防报警、课程思政、旧房装修补贴……）。

后果：污染词会形成假聚类，任何基于它的结论都不成立。

### 处理方式

**① 检索阶段就控制**（最有效）

- 去掉过宽的检索词。例如「健康管理」是几万篇量级的词，
  会把真正要的「主动健康」淹没
- 把 `SU=`（主题，含摘要）换成 `TI=`（篇名），精度高一个量级
- 限定来源类别（CSSCI / 北大核心）

**② 工具内过滤**

```bash
--filter-terms 养老 老年 老龄化 失能 独居 空巢
```

只保留标题/摘要/关键词中出现任一指定词的文献，并报告剔除明细。

**③ 人工核查（不可省）**

跑完图后抽读 10–20 条标题，确认每个聚类的成员真的属于同一领域。

## 六、枢纽词的处理

### 问题

**检索词本身往往出现在半数以上文献中**，会与几乎所有其他词共现，
形成星形枢纽把真实结构压平。

实测：248 篇「主动健康」文献中该词出现 124 次（50%）：

| 处理 | 聚类数 | Q | 图形 |
|---|---|---|---|
| 不剔除 | 4 | 0.338 | 放射状细线，看不出主题 |
| 剔除 | 7 | **0.484** | 主题结构清晰浮现 |

### 处理方式

```bash
--exclude-terms 主动健康
```

**只影响网络构建，不删除文献**——文献仍参与其他关键词的共现统计。

### 判断标准

| 最高频词占比 | 处理 |
|---|---|
| < 20% | 正常 |
| 20% – 40% | 留意，看是否呈星形 |
| **> 40%** | **强烈建议剔除** |

### 论文中的表述

这是规范做法，可以这样写：

> 鉴于检索词「主动健康」出现于 50% 的文献中，为避免其枢纽效应
> 掩盖主题结构，分析时将其从共现网络中剔除。

### 剔除后网络碎裂怎么办

剔除枢纽词后网络可能分裂成多个不连通碎片，
VOSviewer 为框进远处孤立节点会把主网络缩得很小。此时加：

```bash
--largest-component
```

只保留最大连通分量。报告会自动同步（移出的节点不会出现在报告里）。

## 七、分辨率的选择

聚类分辨率 `--resolution` 控制聚类的粒度：

| 网络规模 | 建议值 | 原因 |
|---|---|---|
| < 40 节点 | 0.6 – 0.8 | 默认 1.0 会碎片化（实测 28 节点跑出 9 个聚类） |
| 40 – 150 节点 | 1.0 | 默认即可 |
| > 150 节点 | 1.2 – 1.5 | 需要更细的划分 |

**注意**：VOSviewer 的聚类算法与本地 Louvain 不同，
调整 resolution 后建议观察聚类成员是否仍然同质，而不是只看数量。

## 八、方法论教训汇总

本工具开发过程中，**9 个 bug 全部由真实数据暴露，合成数据一个都没测出来**：

| # | 问题 | 暴露方式 |
|---|---|---|
| 1 | 列表解包错误 | 首次运行即崩 |
| 2 | `clean_term` 括号处理顺序错（反造出括号异常） | 真实数据 120+ 异常词 |
| 3 | 通用 CSV 被误判为 Scopus | 真实 CSV 格式识别 |
| 4 | BibTeX 关键词按逗号分隔却没切 | 定向格式测试 |
| 5 | 自动归并与人工规则形成循环映射 | 真实关键词聚类结果异常 |
| 6 | render 复用过期缓存，导致图表与报告不一致 | 修完 #5 后重跑 |
| 7 | CNKI RefWorks 不带 `ER` 标记，120 条被解析成 1 条 | 真实 CNKI 导出文件 |
| 8 | VOSviewer 用 `-largest_component` 后只回写部分节点 | 图表一致性核查 |
| 9 | 把「0 篇命中」误当作「无相关研究」 | 人工核查邻近领域论文 |

**核心原则：合成数据只能验证「跑得通」，验证不了「对不对」。**
做同类工具时，应尽早引入真实数据做验证。
